# semantic-prim 语义原语适配器（AI 字典）

## 项目简介

现在大家用提示词驱动 AI 生成画面、视频，普遍存在痛点：依靠纯自然语言描述，很容易产生歧义。大模型遇到拿不准的描述，习惯自己脑补内容，只能反复抽卡试错，十抽九翻车。

举个经典例子：文字描述「御剑，真气操控长剑飞行」，AI 常常自动理解为人手握长剑劈砍。

本项目是**开源中立的语义原语规范**，相当于一套 AI 之间通用的 “字典”，**不限定某个软件**，ComfyUI、秋叶工作流、即梦、小云雀、各类多智能体流水线，全部都可以接入使用。

核心规则： 遇到描述存在歧义、信息不足时，**禁止 AI 私自脑补猜测**；低置信度就暂停流程，向人类确认选项。确认完毕之后，生成标准化结构化编码。 AI 与 AI 之间传递确定的结构化参数，不再依赖模糊的自然语言文字，从根源减少理解跑偏。

### 标杆示例

> 原始人话描述：黄昏柳树下，两名剑客对决。男一号施展御剑，手掌不握剑，真气丝线牵引长剑悬空，随意念变换轨迹进攻对手。 歧义识别：“御剑” 存在多种表现形式，系统暂停，向用户确认： 选项 A：手握剑柄挥砍 选项 B：剑脱离手掌，真气牵引悬空飞行 用户选定 B 之后，生成标准编码： `weapon.holder:null`（人物没有握持武器） `weapon.drive:qi-thread` `meta: {lore:"御剑武学意境，仅人类阅读参考，渲染端不依据meta推断画面"}` 下游 AI 读取槽位参数，硬性约束：人物手上没有剑，不会盲目的脑补成手持劈砍。

### 已实现功能

1. 编码双向序列化校验，来回解析骨架稳定
2. 人话 → 编码 规则解析器（text2code.py），抽取镜头槽位并复用歧义回询
3. 歧义关键词识别，低置信度触发质询，消歧结果（如 `weapon.holder:null`）落入编码
4. 信息缺失字段强制标记`null` / 未指定哨兵，禁止模型私自脑补信息
5. Meta 外挂注释，严格区分【客观画面参数】和【故事意境 / 典故】，渲染 AI 不依靠意境描述推断画面

### 适用范围

✅ 通用规范，**不绑定任何单一软件**。 ComfyUI、秋叶工作流、即梦、小云雀、各类多智能体协同系统，都可以编写适配器接入这套标准。

> 本仓库附带的演示 Demo，仅用短剧镜头描述作为试验田，**不是短视频专属工具**，这套原语体系可以拓展到小说、动画、游戏剧情等更多场景。
